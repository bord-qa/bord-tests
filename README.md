# BORD — E2E-тесты платформы app.bord.one

pytest + Playwright (sync API). Тесты гоняются на проде `app.bord.one`
в отдельной организации **BORD QA** (id 42). Тест-учётка состоит только в ней,
поэтому создавать и удалять данные можно, клиентские организации не задеваются.

## Запуск

```bash
pip install -r requirements.txt
playwright install chromium
cp tests/fixtures/users.example.json tests/fixtures/users.json   # вписать учётку
pytest                    # всё (app.bord.one + CRM)
pytest --ignore-glob="tests/test_crm_*.py"   # только платформа app.bord.one
pytest tests/test_crm_*.py                   # только CRM crm.bord.one
pytest tests/test_facturi_*.py               # только Facturi app.facturi.md
pytest -m smoke           # дымовой набор
pytest -m manual          # только ручные блоки (Public API — тратит токены, ecom-100162)
pytest tests/test_auth.py --headed
```

Учётка в CI: секреты `BORD_EMAIL` / `BORD_PASSWORD` (или `USERS_JSON`).

CI — три отдельных прогона со своими отчётами: `e2e.yml` — платформа app.bord.one (ночью 03:00 UTC, всё кроме `tests/test_crm_*.py` и `tests/test_facturi_*.py`), `e2e-crm.yml` — CRM crm.bord.one (ночью 03:30 UTC, только `tests/test_crm_*.py`), `e2e-facturi.yml` — Facturi app.facturi.md (ночью 04:00 UTC, только `tests/test_facturi_*.py`). Очередь у них общая (`e2e-bord`): одновременно не идут, чтобы не мешать друг другу в BORD QA.

## План покрытия CRM (crm.bord.one), с 27.10.2026

Вход в CRM — только SSO из app.bord.one; токен CRM живёт в памяти страницы,
тесты берут его тем же обменом (`helpers/crm.py`). Эталон — API CRM, схема:
`https://crm.bord.one/api/crm/openapi.json` (≈690 путей). В BORD QA включено
ядро (Сделки, Клиенты, Задачи, Календарь, Процессы, Автоматизации, Отчёты,
Мониторинг, Команда, Настройки); остальные плагины (Компании, Лиды, Проекты,
Бронирование, Каналы, Телефония…) выключены.

**Ответственный — только тест-учётка.** В команде CRM BORD QA состоит живой
человек (turcan.maxim@alsodev.com, ID 1244), на нём стартовые примеры.
Примеры («Пример: …», «… (пример)») не трогаем, «Убрать примеры» не нажимаем.

**429 при всплеске запросов.** API CRM режет много одновременных запросов: карточка сделки шлёт
их ~35 разом, и часть получает 429; перезагрузка сразу после неё оставляет доску пустой (список
воронок получил 429, повтора нет). Тесты сделок ждут данные доски и повторяют загрузку через паузу
(`reload_board`, `open_card`). Последовательные запросы лимит не задевают (376 за 30 с — без 429).

## План покрытия Facturi (app.facturi.md), с 02.11.2026

Facturi — финансы BORD на своём домене. Кука BORD до него не доходит: вход кнопкой «BORD» на
форме Facturi (OAuth app.bord.one, `helpers/facturi.py`), один раз на прогон — фикстуры `fx_state` /
`fx_page`. Организация та же — **BORD QA** (id 42), тест-учётка — «Владелец». API —
`app.facturi.md/api/*` по кукам, схема `/api/openapi.json` (≈730 путей). Файлы — `tests/test_facturi_*.py`.

оставляем), Paynet и платёжные шлюзы, подключение реальных банков, «Выйти со всех устройств»,
«Скрыть» у «С чего начать» (для всей организации), письма клиентам, «Задать пароль» в профиле.

## Замечания по поведению

- Вход: `POST /api/admin/auth/email/login`, токен в `localStorage.admin_token`,
  SSO-кука `bord_sso` на `.bord.one`.
- Next.js: кнопки видны до гидрации — клик до `networkidle` может потеряться
  (выход при раннем клике «не срабатывал»).
- «Выйти» на app.bord.one чистит localStorage, но кука `bord_sso` остаётся, и
  crm.bord.one после выхода открывается без пароля. Так задумано (подтверждено 21.10.2026) — не баг.
