# BORD — E2E-тесты платформы app.bord.one

pytest + Playwright (sync API). Тесты гоняются на проде `app.bord.one`
в отдельной организации **BORD QA** (id 42). Тест-учётка состоит только в ней,
поэтому создавать и удалять данные можно, клиентские организации не задеваются.

## Запуск

```bash
pip install -r requirements.txt
playwright install chromium
cp tests/fixtures/users.example.json tests/fixtures/users.json   # вписать учётку
pytest                    # всё
pytest -m smoke           # дымовой набор
pytest -m manual          # только ручные блоки (Public API — тратит токены, ecom-100162)
pytest tests/test_auth.py --headed
```

Учётка в CI: секреты `BORD_EMAIL` / `BORD_PASSWORD` (или `USERS_JSON`).

## Не покрыто (на 27.10.2026)

Ждём починки: перенос системы и смена шаблона на стартовой (ecom-100148),
Public API — 30 из 32 тестов (ecom-100162, нужна чистка отозванных токенов).

Можно дописать: вкладки реестра «Сотрудники», «По должностям», «Входы в BORD»,
«Интеграции» (сейчас только «открывается без ошибок»). «Заблокировать везде»
в увольнении не нажимаем никогда (блокирует учётки в Google/сейфе/BORD).

Схема всего API — `https://app.bord.one/api/openapi.json` (с токеном вошедшего):
там и эндпоинты, которых нет в каталоге MCP BORD.

Нужна вторая тест-учётка в BORD QA: принятие приглашения, смена роли и удаление
сотрудника, «Поручить коллеге» в задачах (единственный другой участник —
живой аккаунт, его не трогаем).

Сознательно не трогаем: «Применить пресет» / «Вернуть исходную» в ролях
(общие настройки организации), «Ждут решения» и привязки у контрагентов
(нужны записи модулей), name.com в доменах (нужны ключи), SSO на app.ecom.md /
app.facturi.md / app.targeting.md (другие домены — решено не проверять).

Не автоматизируем: консоль платформы (нужна платформенная роль), реальную
оплату, отключение модулей, отправку писем со сброса/регистрации (кроме
отдельно согласованных кейсов).

## Замечания по поведению

- Вход: `POST /api/admin/auth/email/login`, токен в `localStorage.admin_token`,
  SSO-кука `bord_sso` на `.bord.one`.
- Next.js: кнопки видны до гидрации — клик до `networkidle` может потеряться
  (выход при раннем клике «не срабатывал»).
- «Выйти» на app.bord.one чистит localStorage, но кука `bord_sso` остаётся, и
  crm.bord.one после выхода открывается без пароля. Так задумано (подтверждено 21.10.2026) — не баг.
